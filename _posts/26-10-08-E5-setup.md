Microsoft 365 개발자 프로그램으로 E5 인스턴트 샌드박스를 만들던 중, 결제 계정을 새로 만들었는데도 설정 화면의 청구 계정 목록에 아무것도 나오지 않는 문제가 있었다. 원인과 해결 과정을 정리한다.

## 환경

- 회사 계정(Entra ID 조직 계정)으로 Microsoft 365 개발자 프로그램 가입
- 샌드박스 유형: Instant sandbox (Configurable sandbox는 선택 불가)
- 결제 계정: 샌드박스 설정 화면의 "새 결제 계정 만들기"로 개인 MCA 결제 계정 생성

## 증상

샌드박스 설정 화면에서 결제 계정을 만든 뒤 ↻ 버튼을 눌러도 `No billing accounts found`가 계속 표시되고, 청구 프로필·송장 섹션이 비활성 상태로 남는다.

![청구 계정 조회 실패](/assets/images/2026-10-08-m365-sandbox/01-no-billing-account.png)

## 확인 과정

### 1. 결제 계정 존재 여부

같은 회사 계정으로 Azure 포털에 로그인한 뒤 Cost Management에서 범위를 확인했다. 결제 계정(Billing account)은 정상적으로 조회됐다.

![Cost Management 개요](/assets/images/2026-10-08-m365-sandbox/02-cost-management-overview.png)

"청구 계정(으)로 이동" → 설정 → 속성에서 확인한 내용은 다음과 같다.

- 유형: Microsoft 고객 계약 (MCA, 셀프 서비스)
- 상태: 활성
- 내 역할: 청구 계정 소유자

![청구 계정 속성](/assets/images/2026-10-08-m365-sandbox/03-billing-account-properties.png)

판매 주소의 이메일이 "확인되지 않음" 상태였지만, 이후 확인해 보니 샌드박스 생성 조건과는 관계가 없었다.

### 2. 청구 프로필 / 청구서 섹션

청구 → 청구 프로필에서 프로필이 활성 상태이고, 역할이 청구 프로필 소유자인 것을 확인했다.

![청구 프로필](/assets/images/2026-10-08-m365-sandbox/04-billing-profile.png)

프로필로 들어가면 왼쪽 메뉴 "청구" 그룹에 **청구서 섹션**이 있다. 샌드박스 화면에서는 "송장 섹션"으로 표시되는 항목이다.

![청구 프로필 개요](/assets/images/2026-10-08-m365-sandbox/06-billing-profile-overview.png)

청구서 섹션도 1개가 활성 상태로 존재했다. 역할의 "상속됨"은 상위 청구 계정 소유자 권한을 물려받았다는 의미다.

![청구서 섹션](/assets/images/2026-10-08-m365-sandbox/07-invoice-section.png)

### 3. Azure 구독

결제 계정 아래 Azure 구독은 0개였다.

![Azure 구독 없음](/assets/images/2026-10-08-m365-sandbox/05-azure-subscription-empty.png)

## 원인

Microsoft Learn 문서(Set up a Microsoft 365 developer sandbox subscription, 2026-09 갱신)의 결제 계정 요구 조건과 대조한 결과는 다음과 같다.

| 조건 | 상태 |
| --- | --- |
| MCA 결제 계정 활성, 계약 수락 | 충족 |
| 청구 프로필 활성 | 충족 |
| 청구서 섹션 활성 | 충족 |
| 권한 (청구서 섹션 기여자 이상) | 충족 (청구 계정 소유자) |
| 해당 청구 프로필/청구서 섹션 아래 Azure 플랜의 활성 구독 | **미충족** |
| 구독 지출 한도 해제 | 해당 없음 (Azure 플랜 구독은 기본적으로 지출 한도 없음) |

문서 트러블슈팅 항목에 따르면 기존 MCA 결제 계정이 목록에 나타나지 않을 때, 사용할 청구 프로필·청구서 섹션 아래에 Azure 플랜으로 만든 활성 구독이 있는지 확인하라고 되어 있다. 구독이 없어서 드롭다운에서 제외된 것이다.

참고로 같은 방법으로 진행한 다른 사례에서는 결제 계정 생성 직후 구독 없이 바로 목록에 나타났다. 어떤 경우에 구독이 필요한지는 문서상 "기존 결제 계정" 기준으로만 설명되어 있어 정확한 판정 기준은 확인하지 못했다.

## 해결: Azure 구독 생성

Azure 포털 → 구독 → **+ 추가**에서 다음과 같이 생성했다.

- 구독 이름: `m365-dev-billing`
- 청구 계정 / 청구 프로필 / 청구서 섹션: 샌드박스에 사용할 항목
- 플랜: Microsoft Azure Plan

![구독 만들기](/assets/images/2026-10-08-m365-sandbox/08-create-subscription.png)

생성 후 상태가 활성, 플랜이 Azure 플랜인지 확인한다.

![구독 생성 완료](/assets/images/2026-10-08-m365-sandbox/09-subscription-created.png)

구독 생성 직후 샌드박스 설정 화면에서 ↻를 누르자 청구 계정·청구 프로필·송장 섹션이 모두 채워졌다.

![청구 계정 선택 완료](/assets/images/2026-10-08-m365-sandbox/10-sandbox-billing-selected.png)

## 관리자 계정 설정

다음 화면에서 샌드박스 관리자 계정을 만든다.

- Admin username: `@` 없이 아이디만 입력
- 비밀번호: 15~20자, 대·소문자·숫자·특수문자 혼합
- "가상의 사용자 16명 모두에게 다른 비밀번호를 사용하세요" 옵션: 체크하면 샘플 사용자 16명에게 공통 비밀번호를 지정할 수 있다. 샘플 사용자로 로그인해 테스트할 일이 있으면 체크하는 편이 편하고, 관리자 비밀번호와는 다르게 정한다.

![공유 사용자 비밀번호](/assets/images/2026-10-08-m365-sandbox/11-shared-user-password.png)

## 결과

샌드박스가 생성되었다.

- Renewable E5 구독, 90일
- 라이선스 25개 중 샘플 사용자 16명에게 할당, 9개 남음

![샌드박스 생성 완료](/assets/images/2026-10-08-m365-sandbox/12-sandbox-ready.png)

## 과금 관련 정리

- 샌드박스 자체는 무료다. 유료 상품을 직접 구매할 때만 청구된다.
- 빈 Azure 구독은 요금이 발생하지 않는다. 리소스를 만들 때부터 과금된다.
- Azure 플랜 구독은 지출 한도가 없으므로, 구독에 리소스를 만들지 않고 예산 경고를 걸어 두었다.
- 2026년 7월 이후 엔터프라이즈 계정으로 발급된 인스턴트 샌드박스는 Copilot 등 추가 라이선스를 샌드박스 안에서 바로 구매할 수 있다. 구매 시 연결한 결제 계정으로 청구된다.
- 결제 계정과 구독이 회사 계정·회사 디렉터리에 묶여 있으므로, 사용이 끝나면 구독 취소와 결제 수단 삭제를 해 둔다.

## 정리

| 단계 | 확인 위치 |
| --- | --- |
| 결제 계정 유형·역할 | Cost Management → 청구 계정 → 설정 → 속성 |
| 청구 프로필 | 청구 → 청구 프로필 |
| 청구서(송장) 섹션 | 청구 프로필 → 청구 → 청구서 섹션 |
| Azure 구독 | 구독 → + 추가 (Microsoft Azure Plan) |

`No billing accounts found`가 계속되면 결제 계정 자체보다 그 아래 Azure 구독 유무를 먼저 확인한다.
